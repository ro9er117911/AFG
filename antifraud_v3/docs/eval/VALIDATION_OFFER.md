# 驗證方案：三種不需要移轉資料的選項

對象：TapPay 技術與法遵團隊
日期：2026-08-12
狀態：提案

---

## 一、先承認問題出在哪

目前的僵局是雙向的，而且雙方的顧慮都成立：

- **我方**：沒有真實通話資料，就無法驗證系統在真實場景的效能。
- **貴方**：把客戶通話資料交給外部廠商，是法遵、個資、與客戶信任的三重風險。
  而且交出去換到的，是一個尚未被驗證的東西。

**我方認為這個僵局的責任在我方的提案方式，不在貴方的謹慎。**

先前的請求形式等於是「請先承擔風險，我們再證明價值」。
任何盡責的法遵團隊都應該拒絕這種提案。

以下三個選項的共同設計原則是：**資料不離開貴方環境。**
把問題從「你敢不敢把資料給我們」改成「你願不願意讓我們在你的牆內被檢驗」。

## 二、三個選項

### ⚠ 前置更正：關於「資料不離開貴方環境」的重要限制

本文件初稿宣稱三個選項都能做到「資料不離開貴方環境」。**這句話在系統的預設設定下
是不成立的，此處更正。**

系統預設的 LLM provider（`LLM_PROVIDER=claude_code`）會呼叫外部 `claude` CLI，
**這是對 Anthropic API 的網路請求——客戶逐字稿會離開貴方環境**。

要真正做到資料不出境，必須改用**地端 `qwen2audio` 路徑**
（`LINE2_BACKEND=qwen2audio`，本機執行 Qwen2-Audio-7B，不呼叫外部 API）。

**但必須同時揭露**：該地端路徑**尚未經過評測**——本次所有結果皆來自
`claude` 文字路徑。因此地端部署的效能是未知數，需要在選項 A 中一併量測。

我方原可以不提這一點——貴方資安團隊大概十分鐘內會自己發現。
先講的理由與本文件其餘部分相同。

---

### 選項 A：地端評測（On-premise Evaluation）

**一句話**：我方交付容器，貴方在自己的環境內對自己的資料執行，只有聚合指標離開。

**前提**：必須設定 `LINE2_BACKEND=qwen2audio` 走地端模型，
且該路徑效能未經評測（見上方更正）。

| 項目 | 內容 |
|---|---|
| 貴方提供 | 一台可執行 Docker 的機器（建議含 NVIDIA GPU，無 GPU 亦可但較慢）；貴方自己的通話錄音與標註，全程留在貴方環境 |
| 我方提供 | 容器映像檔、評測腳本、完整說明文件、`docs/eval/PROTOCOL.md`（預先登錄的評測協定） |
| **離開貴方環境的東西** | **僅聚合統計數字**（HTER、FRR/FAR、各詐騙類型分項、混淆矩陣）。**無任何音檔、無任何逐字稿、無任何個人資料** |
| 我方能否存取 | **否。** 我方無法連線至該容器，無遙測、無回傳通道。可由貴方資安團隊驗證此點 |
| 回答什麼問題 | 系統在**貴方真實資料**上的效能 |
| 預估時程 | 環境建置 1-2 天，評測執行視資料量而定 |

**可稽核性**：容器內執行的評測腳本為明碼，貴方可完整審閱。
評測協定已預先登錄並納入版本控制（含 commit 時間戳），
可證明**指標與判定標準是在看到貴方資料之前就固定的**。

### 選項 B：影子模式（Shadow Mode）

**一句話**：系統只記錄、不告警，跑一段時間後比對，對客戶零影響。

| 項目 | 內容 |
|---|---|
| 貴方提供 | 將通話流複製一份至系統（唯讀）。**系統不接觸告警路徑、不影響任何既有流程** |
| 我方提供 | 部署支援、監控儀表板 |
| **對客戶的影響** | **零。** 系統不發出任何告警、不阻斷任何交易、不改變任何既有行為 |
| 回答什麼問題 | 真實流量下的命中率與**誤報率**——這是離線評測無法回答的 |
| 預估時程 | 建議至少 4-6 週，以涵蓋足夠的真實詐騙事件 |

**為什麼這個選項特別有價值**：離線評測告訴你系統在策展過的資料上表現如何；
影子模式告訴你在**真實流量分布**下表現如何。兩者常有顯著差距，
而後者才是部署決策真正需要的數字。

**風險控制**：因為不接告警路徑，最壞情況是「系統判斷不準，但沒有人受到影響」。
這個選項的下檔風險趨近於零。

### 選項 C：回溯測試（Retrospective Testing）

**一句話**：只用已結案、已確認的歷史詐騙案件，去識別化後評測。

| 項目 | 內容 |
|---|---|
| 貴方提供 | 已確認的歷史詐騙案件錄音 + 對照組正常通話，**經貴方自行去識別化** |
| 我方提供 | 去識別化建議規範、評測執行 |
| 資料處理 | 可在選項 A 的地端架構下執行，資料同樣不離開貴方環境 |
| 回答什麼問題 | 「如果當時系統已上線，這些案件抓得到嗎」——**最容易向管理層說明的形式** |
| 預估時程 | 視案件整理進度而定 |

**這個選項的說服力來源**：用的是已經發生、已經確認的真實案件。
不涉及任何預測或推論，只是回答一個事實問題。

## 三、三個選項的比較

| | A 地端評測 | B 影子模式 | C 回溯測試 |
|---|---|---|---|
| 資料離開貴方環境 | 否 | 否 | 否 |
| 對客戶的影響 | 無 | 無 | 無 |
| 對既有系統的改動 | 無 | 唯讀複製一份流量 | 無 |
| 法遵複雜度 | 低 | 中 | 低 |
| 回答的問題 | 離線效能 | **真實流量效能（含誤報率）** | 歷史案件涵蓋率 |
| 建置成本（貴方） | 低 | 中 | 中（需整理案件） |

**建議順序：C → A → B。**

理由：C 最容易啟動且最容易向管理層說明；A 建立完整的評測基礎設施；
B 提供最有決策價值的數字，但需要前兩者建立的信任基礎。

## 四、我方主動揭露的限制

以下每一項，貴方的技術盡調都會自己發現。先講。

### 4.1 目前沒有可宣稱的準確率數字

現有測試語料為 23 個 `edge-tts` 合成音檔、總長 10.8 分鐘、
實測 **0/23 為電話頻寬**。

**這足以證明系統端到端接通，不足以證明鑑別力。**
在建立真人 + 電話頻寬語料前，我方不會、也不應該對外引用任何準確率數字。

### 4.2 Line 1（合成語音偵測）目前不可商用

現用模型 `nii-yamagishilab/xls-r-2b-anti-deepfake` 為 CC BY-NC-SA 4.0，
非商業授權。已完成替代方案調查：`clovaai/aasist`（MIT，授權已由 LICENSE 檔確認）
為首選底座。

**這是已知的、有解的工程項目，不是隱藏缺陷。**

附帶一個重要事實：**查無任何原生支援 8kHz 電話頻寬的公開 checkpoint。**
無論業界任何廠商，宣稱在電話頻寬做合成語音偵測，都必須有自有語料微調——
沒有人能靠現成模型直接做到。

### 4.3 對抗性風險是持續的

Li et al. (2025, arXiv:2507.16291) 證明用 LLM 改寫詐騙話術，
可讓分類器準確率下降 **30.96%**。詐騙集團同樣在用 LLM。

**這不是可以修好的 bug，是需要持續監控的風險。**
我方已建立改寫攻擊的回歸測試作為長期監控指標。

### 4.4 效能數字的跨域落差極大

Speech DF Arena（2025）在 15 個資料集上評測同一個偵測模型：
EER 從 **0.13% 到 31.96%**，差距 246 倍。

**這是為什麼我方不報單一準確率數字。**
任何廠商給貴方一個漂亮的單一數字，都應該追問是在哪個資料集、哪種條件下量的。

## 五、我方的設計立場：聲學特徵不參與判定

這一點值得單獨說明，因為它是我方與這個產業多數廠商的根本差異。

**系統的風險判定完全不使用聲學特徵。** jitter、shimmer、HNR、F0、eGeMAPS
只用於介面上的描述性呈現，不進入任何判定邏輯。

這可以用程式碼證明，不是行銷語言——`reasoning/fusion.py` 的判定函式簽章
只接受兩個輸入：合成語音分數與話術語意判定結果。沒有任何聲學特徵進入。

**為什麼刻意這樣設計**：四條互相獨立的證據否定「用聲學特徵判斷說謊」：

| 證據 | 結論 |
|---|---|
| DePaulo et al. (2003), *Psychological Bulletin* | 116 篇統合分析，平均效果量 d≈0.25（小效果） |
| National Research Council (2003) | 語音壓力分析「幾乎沒有科學根據」 |
| Damphousse et al. (2007), NIJ 資助 | 實地驗證準確率約等同擲硬幣 |
| Interspeech 2016 ComParE Deception | 官方 baseline UAR 68.3%（隨機 50%）——**同域**成績 |
| SVC 2025 Multimodal Deception Challenge | **跨域**多模態冠軍 62.44%，即每三次判斷錯一次以上 |

貴方若曾接觸過「聲音測謊」類產品，應該知道這個領域的歷史：
Nemesysco 自報 98%、獨立實測約 50%；英國 DWP 採用該技術的試辦計畫
於 2010 年以「不具成本效益」終止。

**我方不做那件事，而且拒絕做那件事的理由寫在程式碼裡。**

## 五之二、我方預期貴方會提出的最強反駁，以及我方的回答

> 「三個選項都要求我們先投入工程資源，去驗證一個你們自己承認尚未有任何鑑別力證據的
> 系統。你們的文件說『足以證明端到端接通，不足以證明鑑別力』。那我們為什麼要用
> 自己的客戶通話當你們的第一個驗證資料集？**先拿公開資料集證明有鑑別力，再來談。**」

**這個反駁是對的，我方接受。**

TeleAntiFraud-28k（ACM MM 2025）可取得、有官方 test split（**400 筆**，
fraud 200 / normal 200 完全平衡），且**完全不需要任何買方的資料**。
取得方式為 auto-approval，是行政步驟而非實質障礙。

該資料集有已發表的 baseline，但**我方不與之比較**：其 baseline 是在該資料集上
微調過的端到端音訊模型，我方是 zero-shot 且需自行 ASR 產生逐字稿——
受測系統形態不同，任何並排數字都會誤導。我方只報自己的 HTER / FRR / FAR。

**我方尚未完成這項測試。** 評測程式已寫好並經單元測試驗證，但截至本文件日期未執行。

因此我方的立場調整為：

> **在完成公開資料集的鑑別力評測之前，我方不請求貴方投入任何工程資源。**
> 本文件的三個選項是「之後」的路線圖，不是「現在」的請求。
> 現在唯一的請求是第六節第 1 項——一次技術對話。

我方認為，在自己能做的測試做完之前就請求對方承擔成本，是先前提案方式的
根本錯誤。這一節就是為了不重蹈該錯誤而寫。

## 六、我方請求貴方提供的

**不是資料。** 是以下三者之一：

1. 一次技術對話的機會，讓貴方的技術團隊審閱我方的評測協定並提出質疑
2. 上述三個選項中任一個的可行性評估
3. 若三個選項皆不可行，請告知阻礙為何——我方會據此設計第四個選項

我方理解貴方尚未被說服。**我方要求的不是信任，是被檢驗的機會。**
