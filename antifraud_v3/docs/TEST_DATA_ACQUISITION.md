# 取得真實電話品質測試錄音

`eval/test_clips/` 現有的測試音檔全部是 `edge-tts` 合成的乾淨寬頻語音（16kHz），不是真實電話
線路的窄頻（narrowband，約 300–3400Hz band-limited）音訊。`audio/quality.py` 的
`detect_bandwidth()` 會判斷上傳的錄音是不是電話品質，但這個判斷邏輯本身需要真的電話品質錄音
才能驗證有沒有正確運作——以下是零成本、不挑手機型號的取得方式。

## 推薦：免費會議橋接電話錄音

使用像 [FreeConferenceCall.com](https://www.freeconferencecall.com/) 這類免費會議橋接服務：

1. 註冊一個免費帳號，取得一組會議撥入電話號碼（PSTN 電話號碼，不是網址）。
2. 用任何手機（市話、行動電話、iPhone、Android 都可以，不需要安裝任何 App）撥打這組號碼加入
   會議。
3. 用第二支手機（或找另一個人）也撥入同一場會議，模擬一通「詐騙電話」對話——可以照
   `eval/test_clips/scam/` 現有檔名的情境唸稿（例如冒充銀行客服要求提供驗證碼、假投資群組等）。
4. 開啟該服務內建的會議錄音功能（錄音是在服務端伺服器完成的，不是手機端，跟撥入的手機型號、
   作業系統完全無關）。
5. 會議結束後從服務的網頁後台下載錄音檔（通常是 wav 或 mp3）。
6. 直接透過前端「上傳錄音分析」分頁上傳，或用 `POST /api/upload-call` 上傳。

這樣拿到的音訊是真實電信網路（PSTN）處理過的窄頻音訊，`detect_bandwidth()` 應該會判斷為
`narrowband: true`（多半是靠頻譜檢查 `reason: "spectral_rolloff"`，而不是 `native_sample_rate`
——會議服務通常會把錄音存成 16kHz 或更高的容器格式，但實際音訊內容仍然是電話頻寬）。

## 其他選項（不是零成本，但更適合系統化蒐集大量測試樣本）

- **Twilio Programmable Voice**：新註冊帳號通常附約 15 美元免費試用額度，用程式撥打電話並用
  `<Record>` 錄音，可以批次產生多通測試錄音，適合之後要擴充回歸測試集時用。
- **RJ11 電話線錄音轉接頭**：只有在手邊已經有市話/總機分機時才值得買（約 US$20–40），接在電話
  線和話機之間，把類比訊號分出一路到 3.5mm line-out。這是唯一能重現「真正電話線頻寬限制」的方案，
  但前提是要有實體市話線路可用。

不建議用「揚聲器外放 + 手機/電腦麥克風收音」——那是聲學耦合（room acoustics + 麥克風本身的頻率
響應），跟電信網路實際處理過的電話頻寬音訊是兩回事，沒辦法驗證這裡要測的東西。
